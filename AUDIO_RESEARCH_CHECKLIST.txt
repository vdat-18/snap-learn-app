✅ 3. AUDIO ENCODING & TRANSMISSION
   ├─ Encoding Method: Base64 (via FileReader.readAsDataURL)
   ├─ Encoding Process:
   │  ├─ Create Blob: new Blob(chunks, { type: 'audio/webm' })
   │  ├─ Read as DataURL: reader.readAsDataURL(audioBlob)
   │  ├─ Result: "data:audio/webm;base64,<BASE64_STRING>"
   │  └─ Extract: result.split(',')[1]
   ├─ Payload Size:
   │  ├─ Raw audio (3s): ~15-30 KB
   │  ├─ Base64 encoded: ~20-40 KB (+33% overhead)
   │  └─ Total JSON: ~20-40 KB
   ├─ Transmission Method: POST /api/pronounce (JSON)
   ├─ Request Body:
   │  {
   │    "vocab_id": "string",

   │    "audio_base64": "string"
   │  }
   ├─ Authentication:
   │  ├─ Authorization: Bearer <JWT_TOKEN>
   │  ├─ X-Child-Id: <CHILD_ID>
   │  └─ Content-Type: application/json

BASE64 ENCODING DETAILS
================================================================================

✅ WHY BASE64?
   ├─ JSON Requirement: Binary audio cannot be sent in JSON directly
   ├─ Simplicity: No multipart/form-data complexity
   ├─ Compatibility: Text-based, works with any server
   └─ Trade-off: +33% file size overhead

✅ ENCODING PROCESS:
   Step 1: Collect audio chunks in array
   Step 2: Create Blob: new Blob(chunks, { type: 'audio/webm' })
   Step 3: FileReader.readAsDataURL(blob) - AUTO ENCODES TO BASE64
   Step 4: Result = "data:audio/webm;base64,<BASE64_STRING>"
   Step 5: Extract base64 part: result.split(',')[1]
   Step 6: Send as JSON parameter

✅ SIZE ESTIMATION:
   3 seconds of speech audio:
   ├─ Raw WebM: 15-30 KB
   ├─ Base64 encoded: 20-40 KB (+33% overhead)
   ├─ JSON metadata: ~200 bytes
   ├─ Total request size: ~20-40 KB
   └─ Network transfer: Acceptable for most networks
